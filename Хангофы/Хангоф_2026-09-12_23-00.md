### 3. Инцидент сессии — потеря правок через `git stash`
При проверке, был ли падающий тест `test_web_routes.py::test_link_generate_creates_code`
пред-существующим (не связан с задачей сессии — подтверждено, не трогали), использовались
`git stash [-- <файлы>] && <проверка>; git stash pop`. Оба раза `git stash pop` печатал корректный
статус восстановления. Тем не менее через несколько шагов `chest_dashboard.py` и
`test_chest_dashboard.py` оказались чистыми (как HEAD), будто правок не было, при этом
`conftest.py` (не участвовал в stash) остался модифицированным — избирательная потеря без видимой
причины. Восстановлено полностью и без потерь: `git fsck --unreachable --no-reflog` нашёл
dangling-коммиты от стешей → `git show <sha> --stat` для идентификации нужного → `git checkout
<sha> -- <path>` вернул содержимое побайтово. Зафиксировано в `ANTI-PATTERNS.md` как новое
правило: не использовать `git stash` для временной изоляции рабочих правок, использовать
временный коммит+soft reset, worktree или ручное копирование файлов в scratchpad.
