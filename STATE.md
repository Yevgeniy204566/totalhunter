### ✅ Закреплена шапка+левая колонка публичной таблицы сундуков (2026-06-23, подтверждено владельцем)

Прошлая попытка (раздельные `<table>` + JS-синхронизация ширины колонок, коммит `0548f9f`) была отклонена владельцем — JS-замер ширины реально ломал вёрстку (шапка съезжала относительно тела). Правильное решение оказалось однострочным: `.public-table-wrap { overflow-y: auto; max-height: 70vh }` → `{ overflow-y: clip }` (без `max-height`). По спецификации CSS `overflow-y: clip` не создаёт скролл-контейнер (в отличие от `auto`), поэтому `position: sticky` у `<thead>` прилипает к реальному вьюпорту, а не к замкнутой 70vh-коробке — низ страницы скроллится свободно. Ширины колонок не трогались вообще, никакого JS. Коммит `2b9edd8`, задеплоено и подтверждено владельцем.

### ✅ Фикс времени «Последнее обновление» на публичной странице сундуков (2026-06-23, подтверждено владельцем)

`Chest.collected_at` пишется как буквальные цифры с ПК бота (`datetime.fromisoformat(item.timestamp)`) в `TIMESTAMP(timezone=True)` колонку без реальной UTC-конвертации — то же самое, что уже происходит с `period_start`/`period_end`. Любой пересчёт через `new Date()`/`toLocaleString()`/ручное добавление `offsetMinutes` на фронте даёт ложный сдвиг (был случай +3ч). Правильно — разбирать ISO-строку строкой (как `formatPeriodPoint`), без объекта `Date` вообще. Коммит `0f95716`, задеплоено, владелец подтвердил точное совпадение.
