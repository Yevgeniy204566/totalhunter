### 7.2 🔴 Находка — 2 анти-паттерна Стадии 1 без контракта/теста

Файл 38, Стадия 1 (`main.py:5156-5178` соответствие в 1.2 «Анти-паттерны»):

> «явный `0` обязан доходить до `coord_manager` как есть, без "0 — то же что не задано"»
> «PLAN-A обязан сохранить это поведение при рефакторинге — не вводить autosave на каждый D-Pad клик»

Оба сформулированы как **обязательные** требования к PLAN-A, но ни разу не превращены в PC-0x
(файл 39) и не получили именованного теста (файл 41) — чистый пропуск между Context и Contract
Extraction, ровно тот класс проблемы, для которого существует Self-Audit.

**Проверено по коду сейчас, что реально доказывает безопасность:**
- `_tune_apply(dx, dy)` (`main.py:5156-5162`) читает целевой `key` через `_tune_get_key()`
  (`main.py:5107`), затем `coord_manager.set_ui_offset(key, ox+dx, oy+dy)`. Само тело `_tune_apply` и
  `coord_manager.set_ui_offset()` (`coord_manager.py:87-90`, `self.ui_offsets[name] = [int(dx), int(dy)]`
  — без проверки на truthiness) — **не входят в изменения PLAN-A** (Stage 4, файл 40, 4.2: только
  источник `_tune_get_key()` меняется с индекса на `self._cal_selected_id`, тело `_tune_apply` не
  трогается). `_tune_apply` нигде не вызывает `_save_profile()` — запись на диск только по явной кнопке.
- Значит оба анти-паттерна защищены СТРУКТУРНО (код, который мог бы их нарушить, вне diff PLAN-A) —
  но единственная реальная точка регрессии: если `_tune_get_key()`-эквивалент в новой реализации
  случайно получит проверку вида `if self._cal_selected_id:` вместо `is not None` (сломает выбор `id`,
  которые оказались falsy-подобными строками — на практике не актуально для строковых id, но сам факт
  «на глаз выглядит безопасно» не был доказан тестом).

**Исправление — добавлено в файл 41 (Test Matrix), не меняет Design/Contracts:**

| Invariant | Normal | Boundary | Failure | Test |
|---|---|---|---|---|
| Явный `0` доходит до `coord_manager` как есть (Stage 1, файл 38, анти-паттерн) | D-Pad уменьшает офсет до `(0, 0)` → `get_ui_offset(id)` возвращает именно `(0, 0)`, не считается «не задано» | Повторный клик после достижения `(0,0)` в отрицательную сторону — переходит в отрицательные числа, не блокируется и не сбрасывается | Реализация вводит `if dx or dy:`-подобную проверку перед `set_ui_offset` — тест ловит несовпадение | `test_zero_offset_persists_through_new_selection_path` |
| Нет autosave на каждый D-Pad клик (Stage 1, файл 38, анти-паттерн) | Клик D-Pad → `coord_manager.ui_offsets` меняется в памяти, файл профиля на диске НЕ изменяется | N/A | `_save_profile()`/запись файла вызвана из обработчика D-Pad-клика (новый источник ключа случайно потянул старый побочный эффект) | `test_dpad_click_does_not_write_profile_to_disk` |

- Новых механизмов (rate limit, дедуп, retry и т. п. — неприменимо к этому PLAN по домену, но проверено
  по методичке) не введено нигде за 6 стадий.
