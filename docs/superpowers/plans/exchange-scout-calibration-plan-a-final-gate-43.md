**Главная находка этой стадии (не было ясно до явной сверки построчно):** spec (`tests-gate-37.md`)
уже называет 8 тестов для Раздела 1 (T-01, T-02, T-03, T-04, T-05, T-06, T-11, T-13). PLAN до этого
раунда правильно переиспользовал только T-03 (PC-06, найдено в раунде ревью Stage 6). Остальные семь
либо получили параллельные PLAN-специфичные имена для того же требования (T-01, T-06, T-11, T-13 —
переименованы/скрёстно сослались этим раундом), либо не имели теста вообще (T-04, T-05 — добавлены
этим раундом; T-02 поглощён более широким уже существующим тестом с явной перекрёстной ссылкой).
Исправлено в файлах 39/41/42 (коммит `1684b5a`), полный список — там же.

**Ни один обязательный контракт спеки не потерян/ослаблен:** проверено построчно C-01…C-06 выше — все
на месте, ни один PC не ослабляет формулировку спеки (например PC-02 требует `==`, не подмножество,
хотя спека формально допускала бы более слабую трактовку C-05).

**Ни один плановый шаг не противоречит спеке:** самопротиворечия, найденные в предыдущих раундах
(`tune_card` 4.2, границы кода Stage 0, PC-04/«не удаляются резко»), были противоречиями ПЛАНА самому
себе, не плана спеке — все закрыты. Отдельных противоречий план↔спека не найдено.

**Каждый acceptance criterion спеки имеет implementation/test path:** да, таблица выше — 100% строк
C-01…C-06 и релевантных A-1/A-3/A-4 имеют путь к коду и тесту по имени.

**План не добавляет изменения вне scope спеки без явного решения:** PositionReader/OCR-geometry/
PLAN-B/Scout Priority — ни одного из них нет в файлах 38-42 как код для изменения (Self-Audit, файл 42,
раздел 7.4); все явно припаркованы отдельно в памяти сессии по решению владельца.

**State transitions/failure semantics/concurrency/resource budgets совпадают со спекой, не
переизобретены:** координатная модель (`coord_manager.calibrate()`/`set_ui_offset()`) не меняется
(C-05, PC-02/PC-05) — буквально то же, что требует спека, не альтернативная реализация.
