## Раздел 1. Единая панель калибровки

**Замысел из входящих.** Сегодня есть 2 основные точки в панели калибровки и отдельный нижний блок тюнинга «ещё на 7 точек с
джойстиком»; пользователи фактически работают только с основной калибровкой. Предложено объединить всё в одну систему на базе
существующей панели, расширенную до **9 точек**: сверху — управление джойстиком и закреплённые параметры/смещения выбранной точки;
ниже — прокручиваемый список всех 9 точек, у каждой свой скриншот и параметры; выбор точки переключает закреплённую область; убрать
разделение «калибровка / tuning»; добавить в раздел ссылку на видео с первой настройкой. Условие: сначала найти все существующие
механизмы и не дублировать логику.

**Что есть в коде (проверено).**
- Две якорные точки: `calibration_ui.py` (249 строк) использует `REF_A`, `REF_B` из `coord_manager` (`calibration_ui.py:21, 235, 244`);
  двухточечная калибровка координат — `coord_manager.py` (138 строк); автокалибровка джойстика — `calibration.py` (169 строк).
- Тюнинг: кортеж `TUNE_TARGET_NAMES` (`main.py:130`) содержит **10** пунктов: `wt_icon, crypt_select, crypt_open, carter, top_accel,
  march_accel, arena_reset, chest_sender, chest_type, chest_collect`. Последние три — группа сундуков (`TUNE_CHEST_GROUP`,
  `main.py:135`), подсвечивается отдельным цветом (`main.py:136`).
- Логика тюнинга — выпадающий список + джойстик: функции `_tune_labels`, `_tune_on_select`, `_tune_apply`,
  `_tune_show_point_crosshair_if_relevant` и др. в `main.py:5047-5156`; подписи локализованы на 19 языков (`cal_tune_*`, `main.py:243…1339`).
- Вкладка калибровки — отдельная кнопка вне сегментированной группы (`_show_calibration_tab`, `main.py:3413`).
- Ссылки на видео в интерфейсе нет (поиск `youtube|видео|video` по `main.py` пуст).

**Расхождение с входящими (не устранено).** Входящие называют 2 + 7 = 9 точек; в коде якорных точек 2 и пунктов тюнинга **10** (7 «старых»
+ 3 группы сундуков), то есть 12. Неизвестно, какие из них должны попасть в «9». Это блокирует раздел до решения владельца.

**Статус в спеках:** нет. Раздел не относится к механике Биржи 2.0 (входящие сами называют его «рефакторингом корпуса»).

**Решения владельца, которые нужны до спеки:**
1. Какие именно точки входят в единую панель (9 из 12? все 12?) и в каком порядке.
2. Отдельная спека по калибровке или часть спеки GUI Биржи 2.0 (рекомендация: отдельная, чтобы не смешивать с 2.0).
3. Источник ссылки на видео (URL) и место размещения.

## Раздел 2. Рекомендуемые значения ползунков

**Замысел из входящих.** На всех пользовательских ползунках, где это имеет смысл: механизм рекомендуемых значений / быстрой загрузки
рекомендуемого значения, зелёная подсветка рекомендуемого диапазона на шкале, не менять математику параметров, **не придумывать новые
числа** без проверки логики и реальных данных.

**Что есть в коде (проверено).**
- В `main.py` 19 ползунков `CTkSlider`. В области нейросети и навигации: `conf_slider` 0.1–0.9 (`:1929`), `nav_wait_slider` 0.4–2.0 (16 шагов,
  `:1949`), `nav_step_slider` 10–20 (`:1981`), `nav_inland_slider` 1–10 (`:2002`), `nav_ocean_slider` 1–15 (`:2067`), `nav_waterpx_slider`
  100–2000 (`:2088`), `nav_diagblind_slider` 0–1 (`:2109`), `nav_footprint_slider` 60–1200 (`:2131`), `nav_delta_slider` 0–20 (`:2152`),
  `nav_pitch_slider` 10–100 (`:2173`). Склепы: 7 ползунков (`:2451-2513`). Комбо: 1 (`:3152`). Сундуки: 1 (`:4575`).
- Механизма «рекомендуемых значений» нет (поиск `рекоменд|recommend` по `main.py` пуст). Есть только значения по умолчанию, задаваемые
  при создании и из `gui_config.json`.

**Статус в спеках:** нет. Раздел затрагивает все режимы бота, а не только Биржу 2.0.

**Решения владельца, которые нужны до спеки:**
1. Список ползунков, на которых нужен механизм (все 19 или только Биржа).
2. Источник рекомендуемых диапазонов: фактические значения из рабочих профилей владельца / измерения; без измерений числа не задавать.
3. Форма интерфейса: кнопка «вернуть рекомендуемое» и/или зелёная зона на шкале (входящие просят и то и другое).
