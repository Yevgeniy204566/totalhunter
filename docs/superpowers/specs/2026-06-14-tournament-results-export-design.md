# Tournament Results Export — Design Spec

**Дата:** 2026-06-14
**Статус:** Approved (brainstorming), готов к написанию плана реализации

## Контекст

В игре открыт диалог «Статистика» (Total Battle) — рейтинговая таблица турнира с
прокручиваемым списком игроков: место, имя (с тегом альянса `[K229]`), и количество
«очков» турнира. Список длинный (видно ~5-6 строк за раз, всего может быть 79+ строк),
плюс отдельная закреплённая строка «твоё место», которая не двигается при скролле.

Эталонный скриншот: `Турнир.png` (корень проекта).

## Цель v1

Локальный CLI-инструмент, который:
1. Скроллит диалог «Статистика» (как `crypt_hunter.py` скроллит список склепов)
2. Распознаёт OCR'ом каждую строку: место, имя игрока, очки
3. Собирает полный список без дублей, включая закреплённую «свою» строку
4. Выгружает таблицу (Место / Игрок / Очки) в Google Sheets

Дальнейшая обработка (сортировка по топу, выдача призов по очкам) — отдельная задача,
делается над уже выгруженными данными. В этой версии — только сбор и выгрузка.

Это standalone-скрипт `tournament_reader.py` в корне проекта, без интеграции в GUI бота
(«пока локально», интеграция в бота — отдельная будущая задача).

## Архитектура

### A. Захват экрана и per-row OCR

- **Захват экрана — двухэтапный** (без зависимости от `coord_manager`/калибровки —
  важно, т.к. этот модуль в перспективе переедет в бота, а позиция окна в
  браузере и в клиенте отличается):
  1. Захват ВСЕГО `monitors[1]` через `mss` — без процентного гадания о
     положении диалога.
  2. **Автодетект bbox диалога «Статистика»** по цвету фона (светлый пергамент):
     `cv2.inRange(hsv, (10,20,150), (40,120,255))` → `cv2.findContours` →
     наибольший контур → `cv2.boundingRect`. Проверено на `Турнир.png`
     (1920×1080): bbox=(578,268,766,546) — находит диалог независимо от того,
     где он оказался на экране (центр/смещение из-за панели вкладок браузера и
     т.п.) и при любом разрешении.
  3. Кроп по bbox → «ROI диалога» — вся геометрия ниже считается относительно
     НЕГО, а не от сырого захвата экрана.
- **Определение row pitch — геометрией, без OCR**: на ROI диалога считаем
  построчные средние яркости (`gray.mean(axis=1)`), берём градиент
  (`abs(np.diff(...))`), ищем индексы где градиент >30 — кандидаты в горизонтальные
  разделители. **Обязательный шаг merge**: отбрасываем кандидаты на y<5 (верхняя
  граница диалога — не разделитель строки), затем сливаем соседние кандидаты в
  пределах 3px в один (толстая линия даёт несколько соседних индексов). Без этого
  шага медиана расстояний даёт 26 вместо 100. `PITCH_PX = медиана(diff(merged))`,
  `ROW_TOP_PX = merged[0] - PITCH_PX`.
  Проверено на `Турнир.png`: raw-пики `[1,112,113,212,213,312,313,412,413,439]` →
  merged `[112,212,312,412,439]` → PITCH_PX=100, ROW_TOP_PX=12 (для ROI 766×546).
  Пик 439 = верхняя граница закреплённой «своей» строки (439/546≈0.805, см. п.B).
  **NUM_VISIBLE_ROWS=4** — 5-я строка (412..512) геометрически перекрывается с
  закреплённой «своей» строкой (начинается на 439), её «очки» не читаются → не
  используется.
- Нарезка ROI на полосы по row pitch (`row = dialog[ROW_TOP_PX+i*PITCH_PX : +PITCH_PX, :]`,
  i=0..3), для каждой полосы — два под-региона как доли (x_frac, y_frac) от
  ширины/высоты полосы (OCR «места» для обычных строк НЕ используется — см. п.B):
  - **Имя**: `x∈[0.29,0.56]`, `y∈[0.05,0.42]` — захватывает `[ТЕГ] Имя`, без линии
    силы под именем. `lang='rus+eng'`, psm 7, без whitelist (поддержка кириллицы:
    «МазаФака»).
  - **Очки**: `x∈[0.74,0.98]`, `y∈[0.25,0.75]` — правая часть строки. `lang='rus+eng'`,
    psm 7, **без whitelist** (whitelist на цифры мешает — хуже распознаёт), дочистка
    `re.sub(r'[^\d]', '', text)` → int. Слово «очки»/«очка» не мешает — отфильтровано
    regex'ом после OCR.
- Предобработка: grayscale → `cv2.resize(fx=4, fy=4, INTER_CUBIC)` →
  `cv2.threshold(thresh=150, THRESH_BINARY)`.
- **Очистка имени**: убираем ведущий тег `^\[.*?\]\s*` (тег всегда первый символ в
  кропе — `[K229]`/`[k229]`), затем хвостовой значок-«ранг» (золотой щит с числом
  22/25/19, идущий сразу после имени) регексом `\s+\S{1,3}$` — OCR этого значка даёт
  то цифры («2», «22»), то мусорные буквы («ZY», «ay»), поэтому стрипается ЛЮБОЙ
  короткий (1-3 симв.) хвостовой токен через пробел, а не только цифры. Известное
  ограничение: реальное имя, заканчивающееся на короткое слово через пробел, тоже
  потеряет это слово — допустимо (best-effort, см. п.D).

### B. Скролл, dedup, конец списка, своя строка

- Скролл: `pyautogui.scroll(-2)` над областью списка (та же величина, что в
  `crypt_hunter.py`), пауза 0.4–0.9с (анти-детект из CLAUDE.md §5), затем повторный
  захват + OCR.
- **Определение «места» — позиционно, без OCR цифр места** (проверено на
  `Турнир.png`: OCR места на фоне медалей/лент ненадёжен — место 5 читается как
  «7», место 4 — пусто; при этом имя и очки читаются отлично):
  - Список всегда открывается с верхней строки → в первом кадре видимым строкам
    присваиваются места `1..N` по порядку сверху вниз.
  - В каждом следующем кадре строки сопоставляются со строками предыдущего кадра
    по значению **очки** (наиболее надёжный OCR-признак, проверено 100% на
    видимых строках) — первая строка нового кадра, чьи очки совпадают с какой-то
    строкой из словаря, даёт «якорь»: `смещение = место_якоря - индекс_строки_в_кадре`.
    Все строки нового кадра получают `место = смещение + индекс_строки`.
  - Если совпадений по очкам не найдено (не должно происходить при шаге скролла
    `pyautogui.scroll(-2)`, но как защита) — кадр пропускается, лог-предупреждение,
    скролл продолжается.
  - **Допущение для проверки на живом тесте**: список при открытии диалога всегда
    стартует с места 1 (своё место показывается отдельно в закреплённой строке —
    подтверждено на `Турнир.png`, где видны места 1-5 в списке + 79 в закреплённой
    строке одновременно). Если на практике список открывается иначе — единичная
    правка константы `STARTING_RANK`, без изменения логики склейки.
- **Dedup**: `dict[место → (имя, очки)]`. Вычисленное (не OCR'енное) место —
  ключ. Пересекающиеся строки между соседними кадрами перезаписывают тем же
  значением.
- **Конец списка**: `cv2.absdiff` между текущим и предыдущим кадром (как
  anti-groundhog в `crypt_hunter.py`), но **без правой полосы скроллбара** (~5%
  ширины ROI) — иначе движение ползунка скроллбара даёт diff > 0 даже когда текст
  списка не изменился, и условие конца списка никогда не выполнится. Если diff по
  оставшейся (текстовой) области по сути нулевой — скроллбар дошёл до низа,
  останавливаемся.
- **Закреплённая «своя» строка** (напр. «79 ЗОЛОТОЙ» на скриншоте — не двигается при
  скролле, отделена линией в самом низу диалога): **не входит в скроллируемую
  область захвата вообще**. Для неё задаётся отдельный статичный ROI (нижняя часть
  диалога, фиксированный % от его высоты — `OWN_ROW_Y_FRAC≈(0.805,1.0)` от высоты
  ROI диалога, проверено на `Турнир.png`), который парсится один раз (в начале или
  конце прогона) и добавляется в итоговый словарь по своему ключу «место». Эвристика
  «разрыв последовательности мест» не используется — она ломается, когда скролл сам
  доходит до места 77-79, совпадающего с местом закреплённой строки.
  Имя/очки закреплённой строки — те же кропы/пайплайн что и для обычных строк
  (см. п.A), применённые к `own_row = dialog[int(0.805*h):h, :]`. «Место» (единственное
  место, читаемое OCR'ом) — отдельный кроп `x∈[0,0.07]`, `y∈[0.15,0.70]` от
  `own_row`, psm 6, whitelist `0123456789`, **threshold=130** (не 150 — иначе пусто).
  Проверено на `Турнир.png`: place=79, name="ЗОЛОТОЙ", points=71896730 — регрессионный
  якорь (п.D).

### C. Экспорт на сайт + структура скрипта

**Конфигурация** — локальный файл `tournament_config.json` (корень проекта, добавлен в
`.gitignore`, НЕ коммитится). Шаблон `tournament_config.example.json` коммитится в репо:

```json
{
  "api_url": "https://api.total-hunter.com",
  "api_token": "REPLACE_WITH_YOUR_TOKEN",
  "alliance_tag": "K229"
}
```

**Скрипт** `tournament_reader.py` (корень проекта):
- Печатает инструкцию «открой диалог Статистика в игре», короткий countdown
- Цикл скролл+OCR из секций A/B, печатает прогресс (`место N: имя — очки`)
- По завершении формирует JSON и отправляет `POST {api_url}/api/v1/tournaments/import`:
  - Заголовок `Authorization: Bearer {api_token}`
  - Тело:
    ```json
    {
      "event_timestamp": "2026-06-14T21:30:00",
      "alliance_tag": "K229",
      "own_data": {"rank": 79, "name": "ЗОЛОТОЙ", "points": 71896730},
      "leaderboard": [
        {"rank": 1, "name": "Scaramouche", "points": 488644262}
      ]
    }
    ```
- При ошибке сети/HTTP (ответ не 2xx) — сохраняет собранный JSON локально
  (`tournament_export_<timestamp>.json`) для повторной отправки вручную, печатает
  понятную ошибку, данные не теряются
- Печатает итоговый статус (успех / локальный fallback)

**Авторизация скрипта**: `api_token` из `tournament_config.json` — отдельный токен для
сбора турнирных данных, не пересекается с пользовательским HWID/лицензией бота.

**ВНЕ СКОУПА этой версии** (отдельный будущий трек — бэкенд сайта):
- Эндпоинт `/api/v1/tournaments/import`, модель БД, авторизация по токену
- Бизнес-логика: грейды штрафов «Древнего» (3 уровня — Порог/Штраф для каждого),
  пропорциональное распределение фрагментов (Top-N или все игроки с очками>0,
  `Фрагменты = Пул * (Очки_игрока / Сумма_очков_аудитории)`, floor + остаток лидеру)
- Страница «личный кабинет» на сайте, где старший альянса видит загруженную таблицу
  и настраивает параметры выше

### D. Обработка ошибок и тесты

**Обработка ошибок**:
- Кадр без якоря по очкам (см. п.B) → пропускаем кадр, логируем, продолжаем скролл
- После `re.sub(r'[^\d]', '', text)` для «очков» строка пустая → очки = пусто, warning
  с вычисленным местом для ручной правки в Sheet
- OCR «имени» — best-effort, без валидации; правится вручную в Sheet при необходимости
- OCR «места» закреплённой строки не цифра → закреплённая строка не добавляется в
  таблицу, warning
- Debug-кропы каждой строки сохраняются на диск (как в `exchange_reader`) для
  диагностики

**Тесты (TDD)**:
- Unit (без OCR/экрана): очистка очков (`re.sub`), стриппер тега `[K229]`, стриппер
  хвостового значка-ранга (`\s+\d{1,2}$`, обязательный пробел — иначе сломает имена
  типа «MavaVaka99»), логика dedup по словарю, логика вычисления места по
  якорю-очкам, логика конца списка (`cv2.absdiff` порог без полосы скроллбара)
- Интеграционный: реальный OCR-пайплайн на фикстуре `Турнир.png` — проверка row pitch
  detection (геометрия, без OCR), что видимые строки распознаются корректно
  (имя/очки), вычисление мест 1..N для первого кадра, и что статичный ROI
  закреплённой строки даёт верное «79 / ЗОЛОТОЙ / 71896730» — регрессионный якорь
- POST экспорт: мок `requests.post`, проверка URL/заголовков/payload — без реальных
  вызовов API в тестах; проверка fallback на локальный JSON при ошибке сети/HTTP
