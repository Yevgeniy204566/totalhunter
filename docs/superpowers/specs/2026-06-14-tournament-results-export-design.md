# Tournament Results Export — Design Spec

**Дата:** 2026-06-14
**Статус:** Approved (brainstorming), готов к написанию плана реализации

## Контекст

В игре открыт диалог «Статистика» (Total Battle) — рейтинговая таблица турнира с
прокручиваемым списком игроков: место, имя (с тегом альянса `[K229]`), и количество
«очков» турнира. Список длинный (видно ~5-6 строк за раз, всего может быть 79+ строк),
плюс отдельная закреплённая строка «твоё место», которая не двигается при скролле.

Эталонный скриншот: `Турнир.png` (корень проекта).

## Цель v1

Локальный CLI-инструмент, который:
1. Скроллит диалог «Статистика» (как `crypt_hunter.py` скроллит список склепов)
2. Распознаёт OCR'ом каждую строку: место, имя игрока, очки
3. Собирает полный список без дублей, включая закреплённую «свою» строку
4. Выгружает таблицу (Место / Игрок / Очки) в Google Sheets

Дальнейшая обработка (сортировка по топу, выдача призов по очкам) — отдельная задача,
делается над уже выгруженными данными. В этой версии — только сбор и выгрузка.

Это standalone-скрипт `tournament_reader.py` в корне проекта, без интеграции в GUI бота
(«пока локально», интеграция в бота — отдельная будущая задача).

## Архитектура

### A. Захват экрана и per-row OCR

- Захват ROI в процентах от `monitors[1]` вокруг диалога «Статистика» —
  без зависимости от `coord_manager` (как `roy/exchange_reader.py`), работает на
  любом разрешении.
- **Динамическое определение row pitch** (на первом кадре): OCR узкой полосы у левого
  края ROI (где сидят круглые номера мест) с whitelist цифр → Y-координаты номеров
  1, 2, 3... → медиана разницы по Y = высота строки в пикселях для текущего
  разрешения/масштаба UI.
- Нарезка ROI на полосы по row pitch, для каждой полосы — три под-региона:
  - **Место** (левый край): whitelist цифр, psm 7
  - **Имя** (после аватара): `lang='rus+eng'`, psm 7, без whitelist (поддержка имён
    типа «МаваВака», «30л0Т0Й»)
  - **Очки** (правая часть): whitelist `0123456789,`, регексом извлекаем число перед
    «очк»
- Предобработка как в `exchange_reader`: grayscale → resize x3-4 → threshold.
- **Очистка имени**: убираем ведущий тег `[K229]` регексом `^\[.*?\]\s*` — он
  одинаковый для всех строк (один кингдом) и не несёт информации.

### B. Скролл, dedup, конец списка, своя строка

- Скролл: `pyautogui.scroll(-2)` над областью списка (та же величина, что в
  `crypt_hunter.py`), пауза 0.4–0.9с (анти-детект из CLAUDE.md §5), затем повторный
  захват + OCR.
- **Dedup**: `dict[место → (имя, очки)]`. Каждый новый кадр домешивается в словарь по
  ключу «место» — пересекающиеся строки между соседними кадрами просто перезаписывают
  тем же значением, точная величина скролла не критична.
- **Конец списка**: `cv2.absdiff` между текущим и предыдущим кадром (как
  anti-groundhog в `crypt_hunter.py`). Если изменений по сути нет — скроллбар дошёл
  до низа, останавливаемся.
- **Закреплённая «своя» строка** (напр. «79 ЗОЛОТОЙ» на скриншоте — не двигается при
  скролле): определяется по эвристике «последняя полоса в кадре, чьё место не равно
  (место предыдущей полосы + 1)» → разрыв последовательности → это закреплённая
  строка. Сохраняется отдельно и добавляется в итоговый словарь по своему ключу
  «место», не участвует в проверке конца списка.

### C. Экспорт в Google Sheets + структура скрипта

**Разовая настройка** (внешние изменения, по согласованию):
1. Включить Google Sheets API на GCP-проекте `digital-arcade-274010` (тот же проект,
   что и существующий service account)
2. Пользователь создаёт новый Google Sheet в своём Drive, делится с
   `gemini-sync@digital-arcade-274010.iam.gserviceaccount.com` как Editor (тот же
   паттерн, что `share_docs_with_sa.py` для 4 docs) → даёт Sheet ID

**Скрипт** `tournament_reader.py` (корень проекта, по аналогии с
`share_docs_with_sa.py` / `create_gemini_sync.py`):
- Печатает инструкцию «открой диалог Статистика в игре», короткий countdown
- Цикл скролл+OCR из секций A/B, печатает прогресс (`место N: имя — очки`)
- По завершении пишет таблицу (заголовок Место/Игрок/Очки + закреплённая своя строка)
  в Sheet через `spreadsheets().values().update()`, перезаписывая каждый запуск —
  идемпотентно, как `replace_doc` в `sync_to_gemini.py`
- Печатает URL таблицы

Авторизация: существующий `service_account.json`, при сборке credentials добавляем
scope `https://www.googleapis.com/auth/spreadsheets`.

### D. Обработка ошибок и тесты

**Обработка ошибок**:
- OCR «места» не цифра → пропускаем строку, логируем, продолжаем
- OCR «очков» не матчит `\d[\d,]*\s*очк` → очки = пусто, warning с номером места для
  ручной правки в Sheet
- OCR «имени» — best-effort, без валидации; правится вручную в Sheet при необходимости
- Debug-кропы каждой строки сохраняются на диск (как в `exchange_reader`) для
  диагностики

**Тесты (TDD)**:
- Unit (без OCR/экрана): регекс парсинга очков, стриппер тега `[K229]`, логика dedup
  по словарю, логика конца списка (`cv2.absdiff` порог), эвристика закреплённой строки
- Интеграционный: реальный OCR-пайплайн на фикстуре `Турнир.png` — проверка, что 6
  видимых строк распознаются корректно (место/имя/очки) — регрессионный якорь
- Google Sheets upload: мок API-клиента, проверка корректности range/payload — без
  реальных вызовов API в тестах
