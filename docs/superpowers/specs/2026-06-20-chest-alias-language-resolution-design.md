# Сундуки — резолв алиасов на родном языке клана (Фаза 3a)

Дата: 2026-06-20

## Контекст

Фаза 2 (`docs/superpowers/specs/2026-06-20-chest-catalog-points-localization-design.md`)
ввела правило «English is the Core»: `ChestTypeAlias.canonical_type` обязан быть
английским ID из эталонного списка 138 сундуков. На практике это означало, что владелец
(носитель русского языка) должен сам находить английское название для каждого сырого OCR-
текста — угадывая или ища по справочнику. Живой пример: строка `Exan → Ёкай` в «Chest
Aliases» так и осталась русской с момента создания, потому что владелец не знал
английского имени сундука «Ёкай».

Предложение от Gemini (`docs/Входящие_Gemini.md`, 2026-06-20): админ должен работать
**только на родном языке** — исправлять опечатки OCR в координатах своего языка, а
английский ID бэкенд находит сам через обратный поиск по глобальному словарю переводов
(`chest_localizations`), который уже существует и уже хранит ровно эту связь
(`canonical_type × language → display_text`).

Владелец подтвердил подход и уточнил детали в брейнсторме (3 раунда вопросов):
1. Сырой→чистый текст в «Chest Aliases» остаётся **пер-клановым** (не глобальным) — два
   клана могут видеть разный кривой OCR для одного сундука (разные экраны/разрешения).
2. Резолв происходит **во время импорта алиасов**, не во время чтения сводки.
3. Если хотя бы одна строка не резолвится — синхронизация останавливается целиком с явной
   ошибкой, без частичной записи.
4. Старые строки, где колонка B уже содержит английский литерал (написаны вручную до этой
   фичи), должны продолжать работать без переделки.

## Решённые архитектурные вопросы

- **Схема БД не меняется.** `ChestTypeAlias.canonical_type` как и раньше хранит итоговый
  английский ID. Меняется только смысл значения, которое админ вписывает в Sheet до
  резолва: теперь это «чистый текст на языке клана», а не готовый английский ID.
- **Резолв — внутри `POST /api/v1/chests/aliases/import`**, до удаления старых строк
  коллектора. Если резолв хоть одной строки `chest_aliases` проваливается — транзакция не
  начинается вообще (ни `DELETE`, ни `INSERT`), ответ `400` со списком **всех** неразрешённых
  строк сразу (не только первой), чтобы владелец чинил все проблемы за один проход.
- **Порядок резолва для одной строки `(raw_type, submitted_type)`:**
  1. Если `submitted_type` точно (после `.strip()`) совпадает с уже известным английским ID
     — он есть как `canonical_type` в `chest_type_catalog` ИЛИ в `chest_localizations` (в
     любом языке) — принять `submitted_type` как итоговый `canonical_type` без перевода.
     Это покрывает старые ручные английские записи и англоязычные кланы
     (`collector.language = "en"`).
  2. Иначе искать `chest_localizations` строку с `language = collector.language` и
     `display_text = submitted_type` (точное совпадение после `.strip()`) → взять её
     `canonical_type`.
  3. Если у коллектора `language` не задан (`None`) — шаг 2 пропускается, доступен только
     шаг 1.
  4. Если ничего не найдено — строка идёт в список ошибок импорта.
- **Язык коллектора, используемый для резолва** — берётся из `payload.language`, если он
  передан в этом же запросе (как и раньше, `pattern`/`language` коллектора обновляются перед
  обработкой алиасов), иначе из уже сохранённого `collector.language`.
- **Формат ошибки 400:**
  ```json
  {"detail": "Chest Aliases: не найден перевод для следующих строк — raw='Exan', clean='Ёкай'; raw='XYZ', clean='Что-то ещё'. Добавьте перевод в Localizations (язык клана) или впишите английское название напрямую."}
  ```
  Если у коллектора не задан `language` и нашлась хотя бы одна нерезолвленная строка —
  отдельное уточнение в том же сообщении: `"у коллектора не задан язык (Collector
  Settings), поэтому обратный перевод недоступен"`.

## Данные — что нужно поправить владельцу перед использованием

- В Sheet `СУНДУКИ учет` → «Localizations» уже есть незаполненная строка `('', 'Ёкай')`
  (строка 19) — владелец допишет туда `Yogwai` в колонку A до того, как заработает резолв
  для этого сундука. Это ручная правка данных, не часть кода.

## Реализация

`server/chest_aliases.py`:
- Новая функция `_resolve_canonical_type(submitted: str, language: str | None, db) -> str`,
  поднимающая `ValueError(raw_type, submitted)` при провале — вызывается для каждого
  элемента `payload.chest_aliases` до начала `delete`/`insert`.
- Сбор всех `ValueError` в список, единый `HTTPException(400, ...)` с агрегированным
  сообщением, если список не пуст.
- Запросы: один `SELECT canonical_type FROM chest_type_catalog WHERE canonical_type = :t`
  + один `SELECT canonical_type FROM chest_localizations WHERE canonical_type = :t` для шага
  1 (или `UNION`, по вкусу реализации); один `SELECT canonical_type FROM
  chest_localizations WHERE language = :lang AND display_text = :t` для шага 2. Чтобы не
  делать N+1 на большой Sheet — допустимо одним запросом подтянуть все строки
  `chest_localizations` коллекторного языка в память (объём — десятки-сотни строк, не
  тысячи) и резолвить по словарю на стороне Python.

`sync_admin_sheet_to_db.py` — **без изменений**: скрипт уже просто передаёт текст из
колонки B как `canonical_type` в payload; смысл текста меняется, но не код, который его
читает и пересылает.

## Тестирование

`server/tests/test_chest_aliases.py` — новые случаи:
- Чистый русский текст резолвится в английский ID через `chest_localizations` (язык
  коллектора `ru`).
- Английский литерал (уже существующий `canonical_type` в каталоге/локализациях) принимается
  без перевода.
- Нерезолвящийся текст → `400`, тело ошибки называет конкретные `raw_type`/текст всех
  неразрешённых строк за один проход (не только первой).
- Коллектор без `language` + нерезолвящийся нелитеральный текст → `400` с уточнением про
  отсутствующий язык.
- Существующие тесты (литерал-английский импорт, дубли, full-replace) продолжают проходить
  без изменений — обратная совместимость.

## Явно вне рамок

- Глобальный (на все кланы) словарь «сырой OCR → чистый родной текст» — отклонено владельцем
  явно, оставляем пер-клановым.
- Нечёткое (fuzzy/AI) сопоставление текста при отсутствии точного перевода — риск неверного
  начисления очков, не делаем. Только точное совпадение после `.strip()`.
- Заполнение полного перевода всех 138 сундуков на русский — ручная задача владельца,
  существующий процесс (лист «Localizations» + `sync_catalog_to_db.py`), не меняется.
- Публичная страница `/chests/{slug}` — отдельная будущая спека (см.
  `project_chest_catalog_next_steps` в памяти).
