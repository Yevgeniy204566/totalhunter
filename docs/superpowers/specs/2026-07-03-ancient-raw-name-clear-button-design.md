# Древний: сохранение сырых OCR-имён турнира + кнопка «Очистить»

**Дата:** 2026-07-03
**Статус:** черновик, ждёт ревью владельца перед переходом к implementation plan

## Проблема

В личном кабинете «Древний» уже есть колонка «Игрок (OCR)» и соседняя колонка
«Правильное имя» (ручное подтверждение через `AncientNameMapping`, задеплоено).
Но сейчас `POST /api/v1/tournaments/import` (`server/tournaments.py`) **на лету**
подменяет сырой OCR-текст на найденное каноническое имя через
`_resolve_player_name()`: точное совпадение с `PlayerAlias.raw_name` или
fuzzy-match (cutoff 0.75) против канонических имён Сундуков. Из-за этого
`AncientRoster.player_name` хранит уже подменённое имя, и колонка «Игрок (OCR)»
на самом деле не всегда показывает то, что реально прочитал бот — сырой текст
теряется безвозвратно для всех успешно сматченных строк.

Владелец хочет:
1. Видеть в кабинете и настоящее сырое имя из турнирной таблицы, и подтверждённое
   правильное имя (с публичной страницы Сундуков) — раздельно, без молчаливой
   автоподмены.
2. Кнопку «Очистить» над колонкой сырых имён, которая одним кликом стирает
   результаты последнего турнирного импорта (имена + очки), не трогая ручные
   записи и записи из «Заполнить из Сундуков».

## Архитектурное решение

### Часть 1 — сырое имя всегда сохраняется как есть

Убрать автоподмену в `tournaments.py`: `_resolve_player_name()`, загрузка
`PlayerAlias`/`canonical_by_fold` и константа `NAME_FUZZY_MATCH_CUTOFF`
удаляются полностью. `AncientRoster.player_name` при импорте всегда = точный
`item.name`, без исключений.

Сопоставление с каноническим именем Сундуков остаётся полностью на стороне уже
работающей системы `AncientNameMapping` (дашборд, `ancients_dashboard.py`):
fuzzy-подсказка (`suggested_name`) считается на лету при каждом GET, лидер жмёт
«Сохранить маппинги» один раз — дальше подтверждённое сопоставление
(`AncientNameMapping.raw_ocr_name == player_name`) применяется автоматически
при каждом следующем GET, пока бот присылает тот же сырой текст. Никаких
изменений в схеме БД для этой части не требуется — колонка «Игрок (OCR)» и
колонка «Правильное имя» уже существуют на фронтенде и уже читают ровно те
поля, которые нужны.

**Осознанно теряемое поведение:** два существующих теста
(`test_fuzzy_match_uses_close_alias_canonical_name`,
`test_fuzzy_match_does_not_match_dissimilar_name`) проверяют именно
автоподмену на импорте — они удаляются/переписываются под новое поведение
(сырое имя остаётся сырым в обоих случаях). Это сознательный откат уже
задеплоенной автоматики ради прозрачности, а не баг.

### Часть 2 — кнопка «Очистить»

Новый эндпоинт:

```
DELETE /web/dashboard/ancients/{slug}/roster/ocr-import
```

- Доступ: `_get_own_or_editor_collector` (как остальные мутации ростера —
  `troop-level`, `rank`, `roster/{player_name}`).
- Удаляет из `AncientRoster` все строки этого `collector_id` с
  `source == 'ocr'`. Строки `source == 'manual'` и `source == 'chests'` не
  трогает.
- Возвращает `{"deleted": <count>}`.
- Если у удаляемой OCR-строки был выставлен `troop_level`/`rank` вручную, эти
  данные пропадают вместе со строкой — тот же trade-off, что уже есть у
  индивидуальной кнопки удаления строки ростера.

Фронтенд (`AncientsPage.jsx`):
- Кнопка «Очистить» над таблицей ростера (рядом с заголовком/ползунком
  точности), с двухшаговым подтверждением — переиспользуется тот же паттерн
  confirm/cancel, что уже есть у удаления отдельной строки (`confirmDeleteRoster`).
- Новый хелпер в `api.js`: `dashboardAncientsClearOcrImport(slug)`.
- После успешного вызова — `refresh()`.

## Изменяемые файлы

| Файл | Изменение |
|---|---|
| `server/tournaments.py` | Убрать `_resolve_player_name`, `PlayerAlias`-резолвинг, `NAME_FUZZY_MATCH_CUTOFF`; хранить `item.name` как есть |
| `server/tests/test_tournaments.py` | Удалить/переписать 2 теста автоподмены под новое поведение |
| `server/ancients_dashboard.py` | Новый `DELETE /{slug}/roster/ocr-import` |
| `server/tests/test_ancients_dashboard.py` | Тесты: успешная очистка только OCR-строк, доступ owner/editor, 404 для чужого коллектора |
| `web/src/api.js` | `dashboardAncientsClearOcrImport(slug)` |
| `web/src/pages/AncientsPage.jsx` | Кнопка «Очистить» с confirm/cancel над таблицей ростера |

## Вне рамок

- Схема БД не меняется — `raw_ocr_name` как отдельная колонка не нужна, эту
  роль уже играет `player_name` после отключения автоподмены.
- Не трогаем `populate-from-chests`, `calculate`, quota-thresholds — они уже
  корректно работают с раздельными raw/mapped именами.
