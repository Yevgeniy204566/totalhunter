Хранить обработанные кадры «незачем».

**Что это значит для спек (правки, которые нужно внести при сверке):**
1. Спека №3, C-02: `pending/` больше не очищается при каждом старте (`exchange-scout-part-a-contracts-design-9.md:21`) — остатки очереди обрабатываются.
2. Спека №3, C-03 и C-08: `found/` не «архив навсегда» (`:22`); кадр удаляется после обработки, а не остаётся в `found/`.
3. Спека №2, A-15: ложные срабатывания больше нельзя проверять по кадрам `found/`; остаётся журнал `scout_results.jsonl` (координаты, `conf`, `box`, `coords_ok`). Оплаченная находка без координат (`coords_ok = false`) остаётся только записью журнала без кадра — вытекает из решения, не блокирует.
4. Спека №3 / Часть B: автоматическое удаление кадров старше 30 минут (правило устаревания, 17c) — оговорка к принципу «ничего не удаляется, кроме обработки».

## Раздел 8. Завершение работы и статусы

**Замысел из входящих.** Когда змейка завершила обход всего королевства: кнопка старта/остановки переходит в **коричневое** состояние («идёт анализ
накопленных скриншотов»); после завершения обработки очереди — **зелёная**. Постоянно видимый небольшой индикатор статуса поверх остальных окон,
предпочтительно в правом нижнем углу, размером с небольшой значок рабочего стола, сообщает, что операция полностью завершена. Предложенные
состояния: зелёный мигающий — бот простаивает и готов; активное состояние — идёт обход или обработка; коричневый — обход завершён, нейросеть
анализирует очередь; зелёный стабильный — очередь обработана; отдельное состояние ошибки — сбой обработки, переполнение очереди, невозможность
отправить данные. Логика относится только к поиску бирж и не меняет другие режимы. Пока в очереди остаются скриншоты, обработка продолжается,
после опустошения останавливается.

**Что есть в коде (проверено).**
- Кнопка Старт: `self.start_button` (`main.py:2210-2216`), высота 56, цвет покоя `MD3["green_btn"]`. При запуске переключается на «Стоп» цветом
  `MD3["error"]` (`main.py:3604-3606`, `:3697-3700`), при остановке возвращается на зелёный (`:3619-3622`, `:3680-3683`); переключатель —
  `toggle_bot` (`main.py:3568`); зеркальная кнопка `_roy_hunt_btn` обновляется вместе с ней. Коричневого состояния нет.
- Постоянного индикатора статуса нет. Есть паттерн небольших окон поверх остальных: `tk.Toplevel` с `overrideredirect(True)` и
  `-topmost` — точка калибровки (`main.py:3473-3475`) и рамка сундуков (`:3510-3512`).
- Определения «обход королевства завершён» нет ни в `navigator.py`, `minimap_reader.py`, `engine.py` (поиск по признакам конца обхода пуст), ни в
  спеках №1–№3.

**Решение владельца 2026-09-18:** «обход королевства» — образное выражение, такой функции нет; змейка работает, пока её не остановят. **`ESC` работает всегда**, во всех состояниях. Состояние «обход завершён → коричневый» из входящих снимается; коричневый цвет нужно привязать к другому событию (см. решения ниже). **Подтверждено владельцем:** коричневый = змейка остановлена (Стоп, `ESC` или автоматическая пауза), очередь ещё не пуста; зелёный = очередь пуста.

**Дополнительные неопределённости:**
1. Цвета: и «простой» (мигающий), и «очередь обработана» (стабильный) зелёные — различаются только миганием; цвет «активного» состояния и состояния
   ошибки не названы.
2. Размер индикатора («сопоставим с небольшим значком рабочего стола») — числа в пикселях не заданы.
3. Поведение индикатора при нескольких мониторах и в полноэкранной игре (окно поверх остальных может мешать кликам по игре).
4. Локализация подписей состояний (19 языков).
5. Как индикатор и кнопка ведут себя при `ESC` (аварийный стоп): что показывается, если очередь не пуста.

**Статус в спеках:** нет.

**Решения владельца, которые нужны до спеки:**
1. ~~«Обход завершён»~~ и привязка цветов — закрыто (коричневый / зелёный подтверждены).
2. ~~Палитра и размер индикатора; нужен ли индикатор~~ — решение владельца: индикатор нужен в первой версии; дизайн в стиле бота (палитра `MD3`), «в пределах разумного», дорабатывается по ходу.
3. ~~`ESC` и обработка очереди~~ — закрыто: `ESC` останавливает змейку, то есть подачу кадров в очередь, но **не** работу нейросети: consumer дообрабатывает очередь. Для остановки нейросети нужна **отдельная кнопка** (решение владельца 2026-09-18). Кадры при остановке нейросети не удаляются (принцип «конвейер»): остаются в очереди до следующего запуска нейросети — на подтверждение. Внешний вид и место отдельной кнопки остановки нейросети — дизайн; состояние индикатора при остановленной нейросети и непустой очереди — дизайн, определяется при проектировании GUI.
