1. Применение миграции на GCP: текущая head-ревизия (`b1a2c3k4s5e6`) определена скриптом по `server/alembic/versions/`, но Alembic на GCP по памяти проекта падает без `DATABASE_URL` — таблица создаётся вручную через `psql`; порядок выкатки определит план (задача деплоя, гейт владельца).
2. Полное содержимое `server/roy.py` после строки 300 и `GET /roy/kingdoms` (:382-390) — не читал; на них спека
   не опирается, кроме факта наличия по docstring (:11).
3. Ревизия серверного кода на GCP соответствует репозиторию — не проверялась.
4. Как именно consumer 2.0 будет вызывать публикацию — за Частью B (конкурентность). Порядок «журнал → публикация»
   зафиксирован контрактом P-08 и **передаётся в Часть B [→ Часть B]**.
5. Nginx `client_max_body_size` на маленький JSON не влияет, но конфиг не читался.
