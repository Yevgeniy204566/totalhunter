## Зачем нужна эта спека

Сегодня в боте — **два независимых механизма** калибровки/тюнинга, которые пользователь воспринимает как
разные вещи, хотя оба крутятся вокруг одной операции («навести джойстик на точку экрана и запомнить
координату»):

1. **Основная калибровка** (`calibration_ui.py`, `coord_manager.py`) — 2 якорные точки `REF_A`/`REF_B`,
   на которых строится вся система координат бота (`coord_manager.to_screen()`/`to_region()`).
2. **Тюнинг** (`main.py`, функции `_tune_*`) — отдельный выпадающий список на 10 пунктов
   (`TUNE_TARGET_NAMES`, `main.py:130`), из которых 3 — группа сундуков (`TUNE_CHEST_GROUP`,
   `main.py:135`), подсвеченная отдельным цветом.

Владелец решил объединить это в **одну панель на 12 целей** (2 якорные + 7 склепы/биржи + 3 сундуки) —
входящие считали 9 (не учли группу сундуков), решение владельца 2026-09-18 явно расширило это до 12.

**Это НЕ часть механики Биржи 2.0.** Сами входящие называют это «рефакторингом корпуса» — калибровка
нужна для всех режимов бота (Склепы, Биржи 1.0, Сундуки, Комбо), не только для Биржи 2.0. Отдельно —
раздел про рекомендуемые значения ползунков тоже затрагивает **все 19 CTkSlider** бота, не только
навигацию/нейросеть.

**Что эта спека НЕ является:**
- не переопределяет математику существующих параметров (входящие прямо просят: «не менять математику»);
- не трогает GUI Биржи 2.0 (отдельный трек);
- не трогает Часть B (конкурентность) — калибровка синхронна, GUI-действие, без фоновых тредов.

## Что уже решено владельцем (не переоткрывать)

1. **Состав точек панели — 12**: 2 якорные (`REF_A`, `REF_B`) + 7 (склепы и биржи) + 3 (сундуки:
   `chest_sender`, `chest_type`, `chest_collect`). Закрыто 2026-09-18.
2. **Видео — только гиперссылка на YouTube**, не встроенный плеер. URL будет предоставлен позже, место —
   раздел калибровки. Закрыто.
3. **Разделение на «Калибровка» и «Тюнинг» убирается** — единая система на базе существующей панели,
   расширенная под все 12 целей. Условие входящих: сначала найти все существующие механизмы (сделано,
   см. ниже), не дублировать логику.
4. **Отдельная спека, не часть спеки GUI Биржи 2.0** (решение владельца 2026-09-19, этот раунд обсуждения)
   — раньше это было открытым вопросом («Отдельная спека по калибровке или часть спеки GUI Биржи 2.0»,
   концепт файл 19, п.2); теперь закрыто выбором последовательности «Калибровка → GUI → Part B Design».
5. **Единый визуальный и поведенческий стиль калибровочных точек** (решение владельца 2026-09-19, этот
   раунд обсуждения). Все 12 точек должны восприниматься пользователем как элементы одной системы
   калибровки: одинаковая логика выбора, отображения, названия, подсказки и визуального обозначения
   точки/области. Пользователь должен однозначно понимать, что именно сейчас калибруется, где находится
   точка/область и какое действие от него требуется. Различия между типами точек допускаются только там,
   где они действительно необходимы по смыслу или механике (например, `REF_A`/`REF_B` — точки, а некоторые
   цели тюнинга технически являются областями, не точками — это различие сохраняется, если оно значимо).
   Визуальная унификация не должна превращаться в перегруженный интерфейс и не должна скрывать
   существенные различия между точкой и областью — не добавлять декоративные элементы, сложную цветовую
   кодировку или лишние состояния только ради «унификации».
