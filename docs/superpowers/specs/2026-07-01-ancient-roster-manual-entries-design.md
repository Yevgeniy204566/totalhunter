# Спека: Сундуки как база для сопоставления имён + ручное добавление участников в Древнем

Дата: 2026-07-01
Статус: одобрено владельцем, готово к написанию плана реализации

## Проблема

Диагностика (задача Г из STATE.md #113) показала: fuzzy-сопоставление сырых
OCR-имён турнирной таблицы Древнего с подтверждёнными именами Сундуков
(`PlayerAlias.canonical_name`, cutoff=0.75) реально пропускает 34.7% игроков
даже при полной базе алиасов (коллектор 229/ELDORADO: 97 алиасов на 95 строк
ростера). Кроме того, даже когда сопоставление УЖЕ подтверждено лидером вручную
через дропдаун «Правильное имя» (`AncientNameMapping`), это подтверждение
сейчас не долетает до таблицы расчёта квоты — `calculate()` в
`ancients_dashboard.py` строит список игроков из сырого
`AncientRoster.player_name`, игнорируя `AncientNameMapping`.

Отдельная, но связанная проблема: часть реальных участников клана вообще не
попадает ни в турнирную таблицу (не участвовал/не отобразился в OCR), ни в
базу Сундуков (не носит сундуки) — но должен получить квоту урона по
Древнему. Нужна возможность добавить такого игрока вручную, с пониманием, что
если он не носит сундуки — это тревожный сигнал (риск скорого исключения из
клана), поэтому ручная запись не должна жить вечно.

## Архитектура

### Часть 1 — таблица расчёта квоты использует подтверждённое имя

В `ancients_dashboard.py` `calculate()`, при сборке `players` для
`split_strategy_b`, каждое сырое `player_name` резолвится: если для него есть
`AncientNameMapping` с `confirmed=True` — используется `mapped_name`, иначе
имя остаётся как есть. Правка одной строки, формулы `ancient_quota.py` не
меняются.

### Часть 2 — ручное добавление участника

**Модель** — три новых поля в `AncientRoster`:

| Поле | Тип | Смысл |
|---|---|---|
| `source` | String(8), default `'ocr'` | `'ocr'` (обычная строка из турнирной таблицы) или `'manual'` |
| `manual_expires_at` | TIMESTAMP(timezone=True), nullable | Для `source='manual'` — момент сгорания записи. `NULL` для `source='ocr'` |
| `rank` | String(20), nullable | Звание — только для отображения, ни в `split_strategy_a`, ни в `split_strategy_b` не участвует (обе стратегии уже сейчас не привязаны к рангу конкретного игрока: А берёт `officer_count`/`veteran_count` числом, Б — по `troop_level`) |

**Помощник времени жизни** — в `server/roy.py` уже есть
`is_trade_routes_active()` (якорь `_EVENT_ANCHOR_TS`, цикл `_EVENT_CYCLE_H`
=144ч, активность `_EVENT_DURATION_H`=24ч). Добавляется переиспользуемая
`next_trade_routes_end() -> datetime` — детерминированная формула ближайшего
завершения ивента «Торговые Пути» (используется как якорь: если ивент сейчас
активен — конец текущего окна; если сейчас пауза — конец следующего окна).
Никакого нового состояния, только формула по тем же константам.

**Эндпоинт** `POST /web/dashboard/ancients/{slug}/roster/manual` — доступ
владелец **или** редактор (`_get_own_or_editor_collector`, как у
`troop-level`/`name-mappings`). Тело: `{player_name, troop_level, rank}`.

Логика:
1. `difflib.get_close_matches(player_name, canonical_names, cutoff=0.75)` —
   если есть похожее имя среди `PlayerAlias.canonical_name` этого
   коллектора — 409 `{"similar_name": "..."}`, не сохраняем молча.
2. Если `AncientRoster` с таким `player_name` у этого коллектора уже
   существует — 409 (не дублируем).
3. Иначе создаём строку: `source='manual'`,
   `manual_expires_at=next_trade_routes_end()`, `place=None`, `points=None`,
   `troop_level`, `rank` как переданы.

### Часть 3 — взаимодействие с импортом турнирной таблицы

`tournaments.py`, полная замена ростера (сейчас: `delete(AncientRoster)
.where(player_name.not_in(incoming_names))`) — добавляется условие
`AncientRoster.source == 'ocr'`: строки `source='manual'` этим шагом никогда
не удаляются.

Апсерт по имени (тот же метод, что уже есть: `select where player_name ==
canonical; if exists: update else: insert`) при обновлении существующей
строки — если её текущий `source == 'manual'`, апдейт дополнительно
устанавливает `source='ocr'`, `manual_expires_at=None`. Игрок, который
начал реально участвовать/носить сундуки, становится обычной бессрочной
строкой; уникальный индекс `(collector_id, player_name)` и так не даёт
второй строки на того же игрока.

### Часть 4 — сгорание ручных записей

Добавляется в уже существующий `server/ancient_retention.py` (не отдельный
файл — он уже отвечает за периодическую уборку данных Древнего) новая
проверка в суточном тике: `DELETE FROM ancient_roster WHERE source='manual'
AND manual_expires_at < now()`. Не путать с существующей 60-дневной чисткой
скрытых коллекторов — это независимое, более частое условие.

### Часть 5 — фронтенд

`AncientsPage.jsx`, над таблицей ростера — форма «Добавить участника
вручную»: поле имени (текст) + селект звания (список как в `ChestsPage.jsx`:
`['', 'Глава', 'Старший', 'Офицер', 'Ветеран', 'Рядовой']`) + три селекта
G/S/M (уже есть `TIERS`/паттерн из Части В техдолга). При 409 с похожим
именем — инлайн-подсказка «Похоже на «Иванов» — использовать это имя?» с
кнопками подтвердить/добавить как есть.

## Тестирование (TDD)

- Часть 1: `calculate()` со Стратегией Б использует `mapped_name` вместо
  `player_name`, когда есть подтверждённый маппинг; без маппинга — как раньше.
- Часть 2: успешное создание ручной записи; 409 при похожем имени; 409 при
  точном дубле; `manual_expires_at` действительно равен ближайшему завершению
  Торговых Путей от `next_trade_routes_end()`; редактор (не только владелец)
  может создать запись.
- Часть 3: полный переимпорт турнира не удаляет `source='manual'` строки;
  реальный импорт с совпадающим именем переключает `source` на `'ocr'` и
  обнуляет `manual_expires_at`.
- Часть 4: тик удаляет просроченные ручные строки, не трогает `source='ocr'`
  и ещё не просроченные `source='manual'`.
- `next_trade_routes_end()`: корректный расчёт и во время активного окна, и
  во время паузы (граничные случаи по образцу существующих тестов
  `is_trade_routes_active()`, если такие есть — иначе новые).

## Зоны риска / открытые решения для плана реализации

- Тестов на `is_trade_routes_active()` в `server/tests/` сейчас нет (проверено) —
  `next_trade_routes_end()` получает собственные новые тесты в тестовом файле
  для `roy.py` (мокая `datetime.now` под конкретные фазы цикла: середина
  активного окна, середина паузы).
- Порядок полей в форме ручного добавления и точный текст подсказки при 409 —
  не критично, разумные значения по контексту, не отдельный вопрос владельцу.
- Свободный ввод имени — сознательно принятый риск (не дропдаун), смягчён
  предупреждением при похожем имени; описано и одобрено владельцем в процессе
  брейнсторма, менять на дропдаун не нужно.
