# Сундуки: квота EM с персональной целью (войска + уровень Героя) — спека 02

> **Серия:** `…-01` несколько квот (сделано, 70b4e17); `…-02` (эта). **Статус:** черновик на ревью
> владельца. **Раунд:** 1. **Stage 8:** не запрошен владельцем. **Класс:** architectural.
> Уже сделано до спеки (владелец попросил сразу, 83357e4): поле «Уровень Героя» (1..999) в кабинете
> «Сундуки → Игроки» и на публичной странице, `player_profiles.hero_level`.

## 1. Цель (владелец 2026-09-26)

Одинаковая норма сундуков EM для всех некорректна: при одном уровне войск сила игрока сильно зависит от
уровня Героя (G9 + Герой 300 ≠ G9 + Герой 550). Нужна **персональная цель квоты EM** для каждого игрока.
**Формулу не выдумывать окончательно:** сначала копим статистику (войска, Герой, сундуки EM по сезонам),
потом подбираем коэффициенты. Поэтому **все коэффициенты — редактируемые** лидером в кабинете.

## 2. Что уже есть (прочитано в коде)

- Квота с `mode: "fixed"` — одна цель на всех (`chest_dashboard.QuotaIn`, спека 01).
- Профиль игрока: `troop_level` строкой «G9 S8 M7» (`chests._TROOP_RE`), `hero_level` int.
- Счётчик квоты игрока — `players[].quotas[slot]` (`chest_summary.pivot_summary`).
- **Пробел для статистики:** снимок закрытого сезона (`summary_json`) не содержит войска и Героя — они
  подмешиваются только в живую сводку (`chests.py` «Enrich each player»). Без этого прошлые сезоны для
  анализа бесполезны.

## 3. Решение

### 3.1 Сбор статистики (делается первым, от него зависит всё остальное)

- При закрытии сезона (авто — `chest_history.archive_one`, досрочно — `close_season_early`) в каждый
  `summary_json.players[]` пишутся `troop_level` и `hero_level` на момент закрытия.
- В кабинете (история сезонов) кнопка **«Скачать статистику»** → CSV: сезон, игрок, войска G/S/M,
  Герой, число сундуков каждой квоты. Этого достаточно, чтобы анализировать в Excel/Google Sheets или
  отдать Claude на подбор коэффициентов.

### 3.2 Персональная цель (режим квоты `per_player`) — реализовано 4f3efa1

**Главная логика (владелец 2026-09-26):** сейчас уровень Героя → личная EM-квота; параллельно копим
статистику; через ~2 недели статистика → анализ → настоящая формула вместо временной.

`цель игрока = max(0, округление( база × (1 + k/100 × (Герой − H₀)/100) ))`

- **Формула предварительная и заменяемая.** Она нужна только чтобы заложить механизм личной цели. После
  накопления статистики вид зависимости и коэффициенты могут быть полностью изменены **без изменения модели
  данных** (квота хранит `mode` + свои параметры; расчёт — одна функция `chest_summary.personal_target`).
  Линейность зависимости не утверждается.
- **Уровень войск в расчёт не входит**: для EM фактически все 9/9/9, войска плохо отражают силу армии —
  поэтому основной параметр Герой. `troop_level` сохраняется в статистике для будущего анализа.
- `база` = цель квоты; `k` — % цели на 100 уровней Героя (−100..100); `H₀` — «средний» Герой (1..999).
  По умолчанию k = 0 → цель = база у всех (как `fixed`).
- Нет уровня Героя → база, ячейка помечается «?».
- **Смысл базы (решение владельца 2026-09-26):** база (например 50 EMC за сезон; число задаёт лидер) —
  **медианная норма, не минимальный порог**. `H₀` — уровень Героя «типичного» активного игрока, при котором
  квота ровно равна базе: слабее ← база → сильнее. Не опираться на крайних игроков (мульты/новички с низким
  Героем могут вовсе не бить EM) — иначе база искусственно занижается. Порог «не ниже базы» не вводится.

### 3.3 Публичная страница

Ячейка квоты `per_player` — прогресс-бар: `собрано / личная цель · %`, заливка градиентом
красный → жёлтый → зелёный по шкале (реализовано 4f3efa1). Заголовок столбца — имя квоты без общей цели.

## 4. Контракты и тесты

| # | Инвариант | Механизм | Тест |
|---|---|---|---|
| E1 | Снимок сезона содержит войска и Героя игроков | `archive_one`/`close_season_early` | `test_close_season_snapshot_has_troop_and_hero` |
| E2 | k = 0 → цель = база; войска не влияют | формула | `test_per_player_defaults_equal_fixed`, `test_per_player_formula_uses_hero_only` |
| E3 | Цель не отрицательная, целая | `max(0, round(...))` | `test_per_player_target_never_negative` |
| E4 | Нет Героя → база, «?» | формула | `test_per_player_missing_hero_uses_base` |
| E5 | Валидация: k в −100..100, H₀ 1..999 | Pydantic `QuotaIn` | `test_per_player_invalid_coefficients_422` |
| E6 | CSV статистики только владельцу коллектора | `_get_own_collector` | `test_stats_csv_owner_only` |
| E7 | Сезоны, закрытые до 02, выгружаются без войск/Героя (пусто), не падают | CSV-выгрузка | `test_stats_csv_legacy_season_blank_fields` |

Адверсариально: игрок сменил Героя посреди сезона → живая цель считается по текущему профилю, архив —
по снимку на закрытие (ожидаемо, фиксируется в подсказке). Отрицательный `k` допустим (если данные
покажут обратную зависимость). Огромный Герой (999) при k=100 → цель ×~7 — ограничено валидацией H₀/k,
отдельный потолок не вводим без данных.
