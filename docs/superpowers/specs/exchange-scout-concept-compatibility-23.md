**Противоречия и неточности самих входящих — состояние:** все закрыты ответами владельца (12 точек; «обход королевства» не существует; 100% = порог паузы;
кадр удаляется после обработки; дедупликация не вводится; Telegram заменён сайтом).

**Правки спек, которые вытекают из решений (сверка спек с концептом — следующий шаг, выполняется по команде владельца):**
1. Спека №3, C-02: не очищать `pending/` при старте; остатки очереди обрабатываются; автозапуск после паузы сохраняет очередь.
2. Спека №3, C-03 и C-08: кадры не хранятся вечно; удаляются после обработки.
3. Спека №2, A-15: проверка ложных срабатываний — по журналу, а не по кадрам `found/`.
4. Спека №1: порядок 4.0 и P-08 остаются (журнал → списание → публикация); добавить, что кадр удаляется после передачи координат.
5. Спеки №1 и №3: оговорка «кроме устаревших» (кадр старше 30 минут удаляется из очереди без обработки); в спеке №3 — источник времени создания кадра.
6. Спека №1 (шапка) и спека №2 (4.10, C-18/C-19 «⛔ заменено»): формулировка «Telegram для 2.0 не используется» уточняется — не используется как канал публикации; временный админский debug-шаг (кроп зоны OCR) требует отдельного контракта (админ-гейт, содержимое, выключаемость).
7. Часть B (не написана): остановка и возобновление без потери очереди; `ESC` останавливает змейку, отдельная кнопка — нейросеть (consumer); non-daemon поток публикации; точка фиксации K; состояние коричневого/зелёного.

## Что остаётся открытым (после ответов владельца)

1. ~~`ESC` и обработка очереди~~ — закрыто: `ESC` останавливает змейку, то есть подачу кадров в очередь, но **не** работу нейросети: consumer дообрабатывает очередь. Для остановки нейросети нужна **отдельная кнопка** (решение владельца 2026-09-18). Кадры при остановке нейросети не удаляются (принцип «конвейер»): остаются в очереди до следующего запуска нейросети — на подтверждение.
2. Ограничение нагрузки от нейросети — нужна ли отдельная настройка (по умолчанию без задержки).
3. ~~Срок показа находки на сайте~~ — закрыто: остаётся 20 минут от публикации, как есть (решение владельца 2026-09-19; 21, п. 5).
4. Числа диапазона скорости для 2.0 и пороги 300/10% — при тестировании.
5. Реализационные детали, не блокирующие спеки: источник счётчика очереди, частота обновления индикатора, URL ролика YouTube.
