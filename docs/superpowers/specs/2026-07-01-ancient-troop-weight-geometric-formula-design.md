# Древний — геометрическая формула веса войск (замена TROOP_QUOTA_PRESETS)

## Контекст

Стратегия Б калькулятора нормы урона по Древним (`server/ancient_quota.py`,
см. [[project_ancient_quota_calculator]] / `docs/superpowers/specs/2026-06-23-ancient-quota-calculator-design.md`)
считала вес игрока через `TROOP_QUOTA_PRESETS[preset][troop_level]` — таблицу-словарь на
13 фиксированных строк вида `"G# S# M#"`. Эти 13 строк — диагональ, где Гвардейцы (G),
Специалисты (S) и Монстры (M) росли по фиксированной игровой прогрессии (M первым, потом
S, потом G).

2026-07-01 ввод `troop_level` в `AncientsPage.jsx` сменился на три независимых
селекта G/S/M (см. [[project_ancient_troop_separate_selects]]) — формат хранения не
менялся (`AncientRoster.troop_level` всё та же строка `"G# S# M#"`), но теперь игрок
может иметь любую независимую комбинацию тиров (например `G7 S9 M8`), которой не было
на старой диагонали → `KeyError` при расчёте.

## Решение

Заменить статическую таблицу на 5 весов (0.05-1.0) чистой геометрической формулой:
каждый следующий тир войска (5→9) в 1.8 раза сильнее предыдущего (подтверждено
владельцем как известный игровой коэффициент). Формула проверена на всех 13 точках
старой диагональной таблицы для всех 5 прессетов — совпадает с точностью ±0.03-0.05
(пример: T8/G7S7M7 старое=0.55, формула=0.56; T9/G8S8M8 старое=0.55, формула=0.56).

Рассматривался альтернативный вариант — вывести веса из сырых игровых характеристик
(Strength/Health) вкладки «Войска» таблицы «СУНДУКИ учёт»
(`1CvfVs4cWUr4EXs7e8uKi2wbT-sQ_gYSIWDw3oJ0Xo64`). Отклонён: сырые числа категории
«Монстры» в ~15-20 раз больше, чем у «Гвардейцев»/«Специалистов» (компенсируется тем,
что монстров берут на атаку меньше, но точного коэффициента количества у нас нет), из-за
чего вес почти полностью определялся тиром M. Также в этой таблице обнаружена опечатка
формулы ×20 (Специалисты, тиры VIII-IX, 3-е значение Strength/Health) — тот же класс
артефакта, что уже правили в `ANCIENT_LEVEL_HP` на уровнях 235-250. Геометрический
вариант точнее совпал со старой ручной таблицей и не зависит от этих сырых данных.

## Формула

```python
def _tier_factor(tier: int) -> float:
    """tier 5..9 -> 1.0, 1.8, 3.24, 5.832, 10.4976"""
    return 1.8 ** (tier - 5)

def troop_weight(preset: str, g: int, s: int, m: int) -> float:
    preset_tier = int(preset[1:])  # "T8" -> 8
    player_power = _tier_factor(g) + _tier_factor(s) + _tier_factor(m)
    preset_power = 3 * _tier_factor(preset_tier)
    return min(1.0, player_power / preset_power)

def parse_troop_level(troop_level: str) -> tuple[int, int, int]:
    """"G7 S7 M8" -> (7, 7, 8). Raises ValueError if malformed or tier outside 5-9."""
```

Cap-правило сохраняется естественно: если игрок на своём тире (или выше) относительно
прессета, `player_power >= preset_power` → `min(..., 1.0)` = 1.0, как в старой таблице.

## Изменения в коде

### `server/ancient_quota.py`
- Удалить `TROOP_STEPS` и `TROOP_QUOTA_PRESETS`.
- Добавить `_tier_factor`, `troop_weight`, `parse_troop_level` (см. выше).
- `split_strategy_b(total, preset, players)` — сигнатура не меняется. Внутри вместо
  `weights[level]` для каждого `(name, level)`:
  ```python
  g, s, m = parse_troop_level(level)
  weight = troop_weight(preset, g, s, m)
  ```
  Игроки с `level is None` по-прежнему исключаются (`excluded`), как раньше.

### `server/ancients_dashboard.py`
- `PATCH /{slug}/troop-level` (строка ~236): валидация `payload.troop_level in
  TROOP_STEPS` заменяется на `parse_troop_level(payload.troop_level)` — попытка парсинга,
  `ValueError` → HTTP 422 (как и раньше при невалидном значении, просто другой источник
  проверки: диапазон 5-9 на каждую букву + порядок `G# S# M#`, а не членство в списке
  из 13 строк).
- Ответ дашборда, отдающий `troop_steps` (строка ~198, уже помечен как мёртвый в
  JSX после сегодняшнего изменения трёх селектов) — удалить как более не нужный.

### Фронтенд
Без изменений. `AncientsPage.jsx` уже собирает и отправляет ту же строку `"G# S# M#"`
через существующий `PATCH /{slug}/troop-level`.

### Данные
Существующие записи `AncientRoster.troop_level` (все в старом диагональном формате)
продолжают работать без миграции — это частный случай новой формулы, не отдельная
ветка кода.

## Тестирование (TDD)

`server/tests/test_ancient_quota.py` (расширить существующий, если есть, иначе создать):
- `_tier_factor(5..9)` — точные значения 1.0, 1.8, 3.24, 5.832, 10.4976.
- `troop_weight` для всех 5 прессетов × всех 13 диагональных комбинаций — сверка с
  числами из старой `TROOP_QUOTA_PRESETS` с допуском ±0.05.
- Cap-правило: тир игрока выше прессета (например преset T7, игрок G9 S9 M9) → вес
  ровно 1.0.
- Недиагональные комбинации (`G7 S9 M8`, `G5 S9 M5`) — не бросают исключение, дают
  разумный (монотонный по каждому тиру) вес.
- `parse_troop_level`: валидный ввод → корректный tuple; тир вне 5-9 → `ValueError`;
  неверный порядок букв (`S7 G7 M8`) → `ValueError`; лишние пробелы/регистр — по текущему
  формату фронтенда (`"G# S# M#"`, ровно один пробел, заглавные буквы) — не нормализуем,
  раз фронтенд всегда шлёт канонический формат.
- `split_strategy_b`: не меняется набор кейсов, кроме замены источника весов —
  существующие тесты (если есть) должны продолжать проходить с новой формулой (числа в
  тестах-регрессиях по диагональным комбинациям поменяются на новые ±0.05, если тесты
  проверяли точные старые значения — обновить ожидаемые числа).

## Явно не входит в эту спеку

- Пересчёт/изменение `ANCIENT_LEVEL_HP` или Стратегии А (по рангу) — не затронуты.
- Условное форматирование недобора/перебора квоты (пункт «Д» из хангоффа сессии #114,
  [[project_ancient_quota_shortfall_formatting]]) — отдельная задача.
- Any UI изменения — сегодняшние три селекта G/S/M уже реализованы и не меняются.
