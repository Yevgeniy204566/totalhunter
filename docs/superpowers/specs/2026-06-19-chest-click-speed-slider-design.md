# Сундуки — ползунок скорости клика (анти-детект джиттер)

Дата: 2026-06-19

## Контекст

В этой же сессии анти-детект пауза между кликами «Открыть» в `chest_reader.py`
(`ANTI_DETECT_PAUSE_RANGE`) была сокращена дважды по явному решению владельца:
`(0.4, 0.9)` → `(0.2, 0.45)` → `(0.16, 0.28)`. Вместо третьей ручной правки константы
владелец хочет ползунок в GUI, который сам управляет этим диапазоном во время сбора.

## Решённые вопросы (из диалога с пользователем)

- **Формула диапазона** (подтверждена примерами, эталон):
  `нижняя = max(0.1, ползунок − 0.1)`, `верхняя = нижняя + 0.2`.
  Проверка: ползунок `0.3` → `(0.2, 0.4)`; ползунок `0.1` (минимум) → `(0.1, 0.3)`.
- **Диапазон самого ползунка:** `0.1` – `1.0` сек.
- **Нижний пол паузы — всегда ≥ 0.1 сек** (защита от двух мгновенных кликов подряд,
  анти-детект). Формула это гарантирует структурно (`max(0.1, …)`), без отдельной проверки.
- **Верхний край на максимуме ползунка не обрезается** — при `1.0` получаем `(0.9, 1.1)`,
  то есть пауза может на максимуме чуть превысить заявленный 1 сек. Это не риск
  безопасности (риск — только слишком короткая пауза), поэтому не корректируется.
- **Размещение в UI:** над кнопкой СТАРТ во вкладке СУНДУКИ.
- **Сохранение:** в `gui_config.json`, сразу при изменении — как `chest_kingdom`/`chest_clan`,
  без отдельной кнопки «Сохранить».
- **Дефолт до первого касания ползунка:** `0.22` (текущий фактический центр `0.16–0.28`,
  чтобы поведение «из коробки» не изменилось у тех, кто уже тестирует).

## Архитектура

### `chest_reader.py` — явный параметр, не мутация модульной константы

Текущий код:
```python
def click_open_button(pos):
    cx, cy = pos
    click_x = cx + random.randint(-ANTI_DETECT_OFFSET_PX, ANTI_DETECT_OFFSET_PX)
    click_y = cy + random.randint(-5, 5)
    pyautogui.click(click_x, click_y)
    time.sleep(random.uniform(*ANTI_DETECT_PAUSE_RANGE))
```
Меняется на параметр с дефолтом — старое поведение (модульная константа) остаётся
поведением по умолчанию, если вызывающий код ничего не передал:
```python
def click_open_button(pos, pause_range=ANTI_DETECT_PAUSE_RANGE):
    ...
    time.sleep(random.uniform(*pause_range))
```
`collect_chests(stop_flag, on_update=None, db_path=DB_PATH, pause_range=ANTI_DETECT_PAUSE_RANGE)`
получает тот же параметр и передаёт его в `click_open_button(pos, pause_range)`.

Это соответствует существующему паттерну проекта — слайдеры передаются как явные параметры
в конструктор/вызов (например `PacmanEngine(joystick_step=int(self.nav_step_slider.get()), ...)`),
а не через мутацию модульного глобального состояния.

### `main.py` — слайдер + вычисление диапазона

- Новый `CTkSlider` (`from_=0.1, to=1.0`, шаг `0.01`) во вкладке СУНДУКИ, над `chest_start_btn`.
- Лейбл над/рядом со слайдером показывает текущее значение, например
  `Скорость клика: 0.22 сек` — обновляется на каждое движение слайдера (`command=`).
- Значение читается/пишется в `gui_config.json` под ключом `chest_click_pause`
  (по аналогии с `chest_kingdom`/`chest_clan` — `_save_gui_config_key` при каждом изменении,
  подтягивается в `setup_chest_tab` при старте, дефолт `0.22`, если ключа нет).
- Новая функция (или инлайн-выражение) `_chest_pause_range(value) -> (float, float)`,
  реализующая формулу `max(0.1, value-0.1), +0.2` — используется в `toggle_chest_bot()`
  перед запуском треда сбора, передаётся в `chest_reader.collect_chests(..., pause_range=...)`.

## Тесты (TDD, `chest_reader.py`)

1. `click_open_button` с переданным `pause_range=(0.5, 0.6)` — `time.sleep` вызывается со
   значением внутри этого диапазона (мокаем `random.uniform`, проверяем переданные границы),
   а не из модульной константы `ANTI_DETECT_PAUSE_RANGE`.
2. Регрессия: `click_open_button(pos)` без аргумента — поведение не изменилось, использует
   модульную константу `ANTI_DETECT_PAUSE_RANGE` как раньше.
3. `collect_chests(..., pause_range=(0.5, 0.6))` прокидывает этот диапазон во все вызовы
   `click_open_button` за сессию (не только в первый).

Формула `_chest_pause_range` (GUI-слой, `main.py`) — не покрывается автотестами по конвенции
проекта (GUI), но это чистая арифметика без побочных эффектов, можно проверить вручную:
`0.1→(0.1,0.3)`, `0.3→(0.2,0.4)`, `0.55→(0.45,0.65)`, `1.0→(0.9,1.1)`.

## Не покрывается автотестами

Сам слайдер, его расположение, сохранение в `gui_config.json`, обновление лейбла — GUI,
проверяется живым запуском после реализации (по той же конвенции, что и фиксы вкладки
СУНДУКИ раньше в этой сессии).
