# Сундуки: несколько квот вместо тумблеров «В пресете» / «Считать в квоту» — спека 01

> **Серия:** `…-01` (эта) — несколько квот; `…-02` — квота EM с уровнем Героя (сбор статистики + редактируемые
> коэффициенты), пишется ПОСЛЕ одобрения 01.
> **Статус:** черновик на ревью владельца. **Раунд правок:** 1. **Stage 8:** не запрошен владельцем (вместо
> него — второй отдельный адверсариальный проход по коду, раздел 5).
> **Класс работы:** architectural (меняется модель данных, API кабинета, публичная страница, архив сезонов).

## 0. Стадия 0 — декомпозиция

Два независимых слоя: (1) модель учёта «несколько квот» — данные/контракты/UI; (2) EM с уровнем Героя —
сбор новой статистики и расчётные коэффициенты. (2) зависит от (1) (квота EM — это одна из квот), обратной
зависимости нет → 01 делается и закрывается первой. В 01 закладывается только точка расширения для 02
(поле `mode` у квоты, раздел 4.1), без формулы и без сбора статистики.

## 1. Цель и решения владельца (2026-09-26)

- Тумблер «В пресете» **убирается** — решено. Пресет = только шаблон: названия сундуков + очки.
- Очки игрока = **единая сумма** всех сундуков «в учёте», независимо от квоты.
- До **3 квот одновременно** в одном сезоне (пример: «Склепы» цель 200 и «EM» цель 50). У каждой — свой
  столбец на публичной странице и своя цель; выполнение подсвечивается независимо.
- Один сундук — **не более одной** квоты.
- Столбец «Epic-склепы» = только настоящие Epic-склепы (ответ «б») — это решается настройкой: лидер
  относит к квоте «Склепы» только нужные сундуки.
- В строке сундука вместо двух тумблеров — **один список «Учёт»**: `Не в учёте` / `В учёте` (очки без
  квоты) / `Квота 1: <имя>` / `Квота 2: <имя>` / `Квота 3: <имя>` (пример одобрен владельцем).

## 4. Дизайн

### 4.1 Данные (одна миграция Alembic, от текущей головы)

- `chest_configurations.quota_slot SMALLINT NULL` + CHECK C1, C2. `counts_toward_quota` **остаётся в БД**
  (откат), кодом больше не читается и не пишется.
- `chest_collectors.quotas JSON NOT NULL DEFAULT '[]'` — `[{"slot":1,"name":"Склепы","target":200,
  "mode":"fixed"}]`. `mode` — точка расширения для 02: сейчас допустимо только `"fixed"` (цель одна на всех);
  02 добавит режим с персональной целью. `target_chests` остаётся в БД (откат), кодом не используется.
- `chest_season_history.quotas_snapshot JSON NULL` — снимок `collector.quotas` на момент закрытия; у старых
  строк NULL.

### 4.2 Сводка (`pivot_summary`)

- Тип показывается и даёт очки ⇔ `is_in_pattern` (как сейчас).
- Новое: у игрока `quotas: {"1": n, "2": m}` — только слоты, присутствующие в `collector.quotas` (C5).
- Совместимость: `quota_chests` = значение слота 1 (или 0) — чтобы старый сайт в окне деплоя не упал.
- `targets` в `/summary`, `/by`, архиве: `{points, chests (legacy = target слота 1), quotas: [...]}`.

### 4.3 Кабинет

- Строка сундука: вместо 2 чекбоксов — `<select>` «Учёт» (5 вариантов, имена квот из настроек; пустые
  слоты не показываются). Отправка `/rows`: `is_in_pattern`, `quota_slot` (старые поля сервер ещё
  принимает 1 релиз, но игнорирует `counts_toward_quota`).
- Настройки сезона: блок «Квоты» — до 3 строк «Название / Цель / 🗑» и «+ Добавить квоту».
  Прежнее поле «Цель по сундукам» уходит в квоту 1.
- Список «Не считать в статистику» у лидера — фильтр по `is_in_pattern` (как сейчас, работает).

### 4.4 Перенос данных (в той же миграции)

Для каждого конфига: `counts_toward_quota AND is_in_pattern` → `quota_slot = 1`; остальное — `NULL`
(`is_in_pattern` не трогаем). `counts_toward_quota = true` при `is_in_pattern = false` (нарушил бы C2) →
`quota_slot = NULL` — это совпадает с текущим поведением: такой тип сейчас скрыт целиком. Для каждого
коллектора: если есть хоть один конфиг со слотом 1 **или** `target_chests IS NOT NULL` →
`quotas = [{"slot":1,"name":"Epic Crypts","target":target_chests,"mode":"fixed"}]`, иначе `[]`.
Имя «Epic Crypts» — как текущий заголовок столбца; лидер переименует.

### 4.5 Публичная страница

- Вместо одного столбца «Epic-склепы» — по столбцу на каждую квоту из `targets.quotas` (имя квоты, число,
  подсветка при `>= target`), сортировка и строка средних — как у остальных столбцов.
- `quotas` пуст и нет legacy-данных → квотных столбцов нет.

## 5. Адверсариальный разбор (2 прохода, второй — по коду)

1. *Лидер удалил квоту 2, а у сундуков остался `quota_slot=2`* → C5: слот игнорируется, очки сохраняются;
   при следующем «Сохранить» строк UI покажет «В учёте». Контрпример «сундук пропал из очков» невозможен:
   очки зависят только от `is_in_pattern`.
2. *Два окна кабинета одновременно сохраняют строки* → как и сейчас: `/rows` — полная замена в одной
   транзакции, выигрывает последний (last-write-wins). Новых гонок не добавляется; уникальности слотов
   между строками нет по замыслу (много сундуков в одной квоте).
3. *В `quotas` пришло `slot: 0`, `slot: "1"`, дубликат слота, 4 квоты, пустое имя, target < 0* → 400/422
   Pydantic (C4); имя 1..40 символов, target `int >= 0` или null.
4. *`query_summary_rows` берёт `max(...)` по конфигу* — у конфига один `catalog_id` на коллектор (дедуп в
   `/rows`: `seen_catalog_ids`), поэтому `max(quota_slot)` = его значение, не смесь. Проверено в коде
   `chest_dashboard.py:350-359`.
5. *Старый снимок архива без `quotas_snapshot`* → C7 fallback. *Новый снимок, квоты пустые* → нет столбцов.
6. *Бот* — конфиги не читает и не пишет (импорт идёт в `chests`), не затронут.
7. *Окно деплоя: сервер новый, сайт старый* → старый сайт шлёт `counts_toward_quota`: сервер его
   игнорирует (пишет `quota_slot=NULL`) — **риск потери отметки квоты**, если лидер сохранит строки старым
   сайтом. Смягчение: сайт и сервер выкатываются подряд в течение минут; план фиксирует порядок
   «сервер → сайт → проверка». Принимается как ограничение окна деплоя.
