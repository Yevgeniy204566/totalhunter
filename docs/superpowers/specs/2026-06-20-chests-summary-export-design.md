# Сундуки — публичная сводка (GET endpoint) + интерим-экспорт в Google Sheets

Дата: 2026-06-20

## Контекст

Backend-фундамент Сундуков (`server/chests.py`, `docs/superpowers/specs/2026-06-18-chests-backend-foundation-design.md`)
задеплоен на GCP — данные пишутся через `POST /api/v1/chests/import`, но прочитать их
обратно не из чего: только `POST /import`, никакого GET. Владелец хочет видеть сводку по
сундукам (кто сколько принёс каких сундуков) — сначала быстро, в Google Sheets, потом
красиво на сайте.

Эта спека покрывает **только** новый GET-эндпойнт сводки и интерим-скрипт экспорта в Google
Sheets. Веб-страница на сайте — отдельная будущая спека, использует тот же эндпойнт.

## Решённые архитектурные вопросы

- **Один источник правды для обоих потребителей.** Новый `GET /api/v1/chests/summary/{slug}`
  отдаёт уже агрегированный JSON (игрок × тип сундука → count). И скрипт экспорта в Sheets,
  и будущая веб-страница читают один и тот же эндпойнт — backend не переделывается, когда
  дойдём до сайта.
- **Slug = публичный доступ без авторизации.** `ChestCollector.slug` уже спроектирован как
  «непредсказуемый публичный идентификатор для будущего дашборда» (`models.py:382`,
  `secrets.token_urlsafe(16)`). Эндпойнт публичный (без Bearer/hwid) — знание slug само по
  себе является правом доступа, как share-ссылка. Несуществующий slug → 404.
- **Агрегация на сервере, не на клиенте.** `SELECT sender_canonical, chest_type_canonical,
  COUNT(*) FROM chests WHERE collector_id=? GROUP BY 1, 2` — одним запросом, без выгрузки
  тысяч строк в скрипт/браузер для агрегации там.
- **Источник данных — продовая БД на GCP**, не локальный `chest_results_export.csv` (это
  тестовый артефакт с локальной машины, не имеет отношения к проду).
- **Скрипт экспорта переиспользует существующий `service_account.json`** (используется в
  `sync_to_gemini.py` для Google Docs API). Добавляем scope
  `https://www.googleapis.com/auth/spreadsheets`. Целевой Google Sheet должен быть расшарен
  на email сервис-аккаунта (как делал `share_docs_with_sa.py` для документов) — это ручной
  шаг владельца перед первым запуском, не часть кода.
- **Скрипт запускается вручную, повторно**, когда владелец хочет обновить снимок данных —
  без cron/автоматизации на сервере. Каждый запуск полностью перезаписывает лист (а не
  дописывает) — простой и предсказуемый источник правды, без риска дублей при повторных
  запусках.

## API

### `GET /api/v1/chests/summary/{slug}`

Ответ `200`:
```json
{
  "kingdom": "...",
  "clan": "...",
  "chest_types": ["Сундук Эпического Монстра", "..."],
  "players": [
    {"name": "Tureglil", "counts": {"Сундук Эпического Монстра": 12, "...": 3}, "total": 15}
  ],
  "totals": {"Сундук Эпического Монстра": 340, "...": 50, "grand_total": 1276}
}
```
Сортировка `players` — по `total` убыв. `404`, если slug не найден.

Реализация — в `server/chests.py`, рядом с `import_chests`: один SQL-запрос
`GROUP BY sender_canonical, chest_type_canonical`, затем pivot в Python (словарь
`{(sender, type): count}` → список игроков + список типов + totals).

## Скрипт экспорта (`export_chests_to_sheet.py`, корень репозитория)

По аналогии с `sync_to_gemini.py`:
- Константы в начале файла: `SLUG`, `SHEET_ID`, `SA_PATH = service_account.json`.
- `requests.get(f"{API_BASE}/api/v1/chests/summary/{SLUG}")`.
- Строит 2D-массив (заголовок: «Игрок» + типы сундуков + «Итого»; строки — игроки;
  последняя строка — «ВСЕГО» из `totals`).
- `sheets().spreadsheets().values().update(... valueInputOption="RAW")` с
  `range="A1"` после `clear()` всего листа — полная перезапись, без накопления старых строк.
- Печатает в консоль ссылку на лист и количество строк после успешной записи.

## Тестирование

- `server/tests/test_chests.py`: новый тест на `GET /summary/{slug}` — корректная агрегация
  по нескольким игрокам/типам, сортировка по total, 404 на неизвестный slug, пустой
  коллектор (0 сундуков) → пустые списки без ошибки.
- Скрипт экспорта — не покрывается автотестами (внешний side-effect на Google API), проверяется
  вручную владельцем после первого запуска (раздел «дальше» в плане).

## Явно вне рамок

- Веб-страница на сайте (`web/src/ChestsPage.jsx`) — следующая спека, переиспользует этот
  GET-эндпойнт.
- Автоматизация экспорта (cron на GCP, авто-запуск при импорте) — не запрошено, делаем по
  явному ручному запуску.
- Фильтры по дате/типу в `summary` — не запрошено, сводка за всё время сборщика.
