## Стадия 8. External Agent Review — не запрошен владельцем

**Унифицировано под золотое правило 2026-09-18 (2026-09-19, этот раунд):** Stage 8 выполняется только по
прямому запросу владельца; агенты без такого запроса не запускаются (`CLAUDE.md`,
`docs/РАБОТА-С-ДОКУМЕНТАМИ.md`). Запроса не было, поэтому Stage 8 для Части A **не выполнялся** — вместо
него Claude сам прошёл второй, отдельный адверсариальный проход по Стадии 5 (A-1…A-13), читая код лично.
Отсутствие Stage 8 по этой причине **не блокирует Final Gate**.

История вопроса до унификации (сохранена как факт, не как действующий процесс): до золотого правила
документ использовал более старую, четырёхусловную версию протокола Stage 8 и по ней держал статус «не
закрыт», потому что модуль в целом конкурентный (условие «нет concurrency» не выполнялось). Раунд 1 пропуск
предлагал, раунд 2 (появление денежного контракта C-17) отменял пропуск, раунд 3 (вынос денег в Часть A-М)
возвращал к раунду 1, но решение не закрывалось. Золотое правило сделало этот пересчёт устаревшим: Stage 8
в текущей версии протокола не привязан к четырём условиям, а привязан только к явному запросу владельца.

**Остаётся в силе независимо от Stage 8:** когда будет написана **Часть B** (конкурентность, несколько
writer'ов, shutdown), её собственное решение по Stage 8 принимается заново по актуальному золотому правилу
— по запросу владельца, а не автоматически. Внешнее ревью Части B (когда бы оно ни было запрошено) должно
проверять файловые контракты Части A совместно с конкурентностью, а не изолированно, поскольку A-4, A-5 и
A-12 закрыты лишь частично, **и отдельно — денежные последствия конкурентности** (два процесса на одном
`hwid` дают две серии списаний с одного баланса, **[→ Часть A-М]**).
