# Сундуки — UX-фиксы вкладки + накопительный счётчик невыгруженного

Дата: 2026-06-19

## Контекст

Клиентский модуль «Сундуки» (`chest_reader.py` + вкладка СУНДУКИ в `main.py`) реализован,
живо-протестирован, backend-фундамент задеплоен (см. STATE.md, 2026-06-19). Пользователь
обнаружил три проблемы при реальном использовании:

1. Список типов сундуков (`chest_counts_frame`) растёт без ограничения и выталкивает кнопку
   «ОТПРАВИТЬ НА СЕРВЕР» (а на маленьких окнах — практически всё ниже статуса) за пределы
   видимой области. Нет скролла.
2. Кнопки СТАРТ и ОТПРАВИТЬ НА СЕРВЕР нужно поменять местами.
3. Счётчик на экране после СТОП показывает только что собранное **за последний прогон**,
   а не реальный остаток невыгруженного. Сама отправка (`send_chests_to_server`) уже шлёт
   ВСЕ `is_synced=0` записи из БД (накопительно), но дисплей этого не отражает — после
   нескольких циклов старт/стоп без отправки на экране видно только последний кусок,
   а не сумму.

## Решённые вопросы (из диалога с пользователем)

- **Порядок кнопок** — простой своп. Новый порядок сверху вниз: Королевство/Клан →
  **ОТПРАВИТЬ НА СЕРВЕР** → статус → [скролл-список типов] → «Всего» → **СТАРТ**.
- **Разбивка по типам** (верхний список) тоже становится накопительной из БД, а не
  «живым счётчиком» только текущей сессии — пользователь явно выбрал этот вариант.

## Архитектура

Никаких новых таблиц/миграций — расширяем существующую `local_chests` (SQLite,
`chest_buffer.db`), у которой уже есть `chest_type` + `is_synced`.

### Источник правды для счётчика — `get_unsynced_counts(conn)`

Новая функция в `chest_reader.py`:
```python
def get_unsynced_counts(conn) -> dict[str, int]:
    """{chest_type: count} по всем is_synced=0 записям — единый источник правды
    для «итогового невыгруженного количества» (live-тикер, дисплей после стопа,
    дисплей на старте вкладки)."""
```
`GROUP BY chest_type WHERE is_synced = 0`.

### `collect_chests()` — счётчик читается из БД, не из локального `Counter`

Сейчас `counts` — это `collections.Counter()`, обнуляемый при каждом вызове функции
(т.е. при каждом новом прогоне СТАРТ). Меняем: после каждой `insert_chest` (и в финальном
`return`) счётчик, передаваемый в `on_update` и в результат, берётся через
`get_unsynced_counts(conn)` вместо локального `Counter`.

Эффект: один источник данных для трёх мест отображения (live во время сбора, после СТОП,
при открытии вкладки) — без отдельной логики «сложить старое с новым», накопление
происходит автоматически, потому что и старые, и новые строки уже физически лежат в
одной таблице с одним и тем же фильтром `is_synced=0`.

`items` (список конкретных находок текущей сессии) в возврате остаётся как есть — он
используется только тестами, в `main.py` не читается (`send_chests_to_server` сам берёт
`get_unsynced()` напрямую из БД).

### `main.py` — три точки вызова

1. **`toggle_chest_bot()` (старт сбора)** — вместо `self._update_chest_counts_display({})`
   подтягивает текущий невыгруженный остаток из БД и показывает сразу (без вспышки «0»,
   если остаток уже есть от прошлых прогонов).
2. **`send_chests_to_server()`** — после успешного `mark_synced` дополнительно вызывает
   `self.after(0, lambda: self._update_chest_counts_display({}))` (в БД действительно не
   осталось `is_synced=0` записей — дисплей обязан показать 0).
3. **`setup_chest_tab()`** — при создании вкладки сразу подтягивает текущий остаток из БД
   (через `chest_reader.get_unsynced_counts`), чтобы после перезапуска бота счётчик не
   показывал 0, пока пользователь не нажмёт СТАРТ.

### UI

- `chest_counts_frame`: `CTkFrame(fill="both", expand=True)` → `CTkScrollableFrame`
  фиксированной высоты (260px). Список разрастается внутри своих границ, остальные
  виджеты вкладки больше не двигаются.
- Порядок `.pack()`: Королевство/Клан-карточка → `chest_send_btn` → `chest_status_label` →
  `counts_card` (со скролл-фреймом внутри + `chest_total_label`) → `chest_start_btn`.
  (Сейчас порядок: …→ `chest_start_btn` → статус → `counts_card` → `chest_send_btn`.)

## Тесты (TDD, `test_chest_reader.py`)

1. `get_unsynced_counts` группирует по типу, игнорирует `is_synced=1` строки.
2. После `mark_synced` всех строк → `get_unsynced_counts` возвращает `{}`.
3. `collect_chests` с уже существующими невыгруженными строками в БД (вставлены до вызова)
   + новыми находками за сессию → итоговый `result["counts"]` = сумма старого и нового по
   каждому типу (накопительно через БД, не через `Counter`).
4. Регрессия: существующие тесты (`test_collect_chests_counts_and_persists`,
   `test_collect_chests_stops_immediately_when_flag_already_set`) остаются зелёными без
   изменений — в них БД создаётся пустой, поэтому накопительный путь даёт тот же результат,
   что и старый.

## Явно не покрывается автотестами

UI-уровень (`main.py`, customtkinter) — порядок виджетов, сам скролл, обновление дисплея
в трёх точках вызова. По конвенции проекта (другие вкладки GUI тоже не покрыты
unit-тестами) — проверяется живым запуском приложения после реализации.
