#### 2. Исправление архитектуры ROY SSE (предыдущая сессия, доработана)

**Проблема:** SSE-соединение к `/roy/status-stream` было всегда открыто, даже если игрок вообще не использует РОЙ.

**Решение:** SSE теперь открыто **всегда** (для фоновых звуковых уведомлений о новых координатах), но `GET /roy/pool` отправляется **только по событию** — когда игрок переключается на вкладку БИРЖИ или РОЙ. Никаких polling-запросов каждые N секунд.

#### 3. Таблица механики РОЙ (итоговое понимание)

| Ситуация | Действие | Результат |
|----------|----------|-----------|
| Ивент НЕ активен | — | РОЙ не работает совсем: ни drain, ни начисление |
| Ивент активен, тумблер РОЙ выкл | — | РОЙ молчит |
| Ивент активен, тумблер РОЙ вкл, поиск бирж СТОИТ | idle раз в 60 с | −30 сек из РОЙ-баланса |
| Ивент активен, тумблер РОЙ вкл, поиск бирж ИДЁТ | scan раз в 28–30 с | +45 сек к РОЙ-балансу (коэф 1.5×) |
| Смотришь пул = тумблер вкл | pool view = использование РОЙ | drain идёт всегда, это и есть оплата |

**Ключевой вывод:** drain не зависит от вкладки — если тумблер включён и ивент активен, время тратится всегда. Это плата за доступ к пулу координат.

#### 4. Аудит безопасности: система алмазов

Запустили два агента — аудит биллинга и аудит модели доступа.

**Найденные уязвимости (оценка):**

- Нужен более широкий паттерн, например:
  ```python
  text = re.sub(r'\s*[\(\{\|\[iI]\s*[KkКкRr]:?\s*\d+.*', '', text)
  text = re.sub(r'\s+[KkКкR]:?\s*\d{1,3}[\s:].*', '', text)
  ```
- Или: обрезать по ГОРИЗОНТАЛЬНОЙ позиции — детектировать где начинается синий подчёркнутый текст
